# 모바일 웹 골프 게임 서비스화 계획

작성일: 2026-09-08

## 기본 방향

게임을 더 크게 만드는 것보다 사람들이 다시 찾아오고 공정하게 경쟁할 수 있는 구조를 먼저 만든다.

- 기준: 1인 개발, 주 40시간, 월 예산 10만원 이하.
- 순서: 모바일 웹 베타 → 온라인 랭킹 → 재방문 검증 → 수익화.
- 앱스토어 출시는 뒤로 미룬다.
- 이 문서는 계획이며, 계정 생성·유료 구독·프로덕션 배포 승인과는 별개다.

## 1. 현재 상태와 빠진 것

현재 게임은 9홀을 플레이하고 내 기기에 기록을 남기는 모바일 웹 게임이다. 홀 전장은 100~180m이며, 홀인원과 핀까지의 거리로 점수를 매긴다. 현재 일·주·월 기록은 다른 사용자와 경쟁하는 온라인 랭킹이 아니라 기기 내 개인 기록이다.

| 우선순위 | 필요한 것 | 이 게임에서의 의미 |
|---|---|---|
| 1 | 이용 데이터와 오류 파악 | 첫 샷 전에 나가는지, 9홀을 완주하는지 확인 |
| 2 | 신뢰할 수 있는 온라인 기록 | 다른 사람과 비교하고 점수 조작 방지 |
| 3 | 재방문 이유 | 오늘 코스·내 순위·어제보다 나아진 기록 |
| 4 | 운영과 복구 | 배포 오류 되돌리기·기록 백업·문의 대응 |
| 5 | 출시 준비 | 이름·도메인·라이선스·개인정보·이용조건 정리 |

로그인이 있어야 서비스인 것은 아니다. 다만 일·주·월 경쟁 랭킹에는 서버가 필요하다.

## 2. 첫 2주: 소규모 베타

목표는 소규모 테스트에 내놓을 수 있는 안정적인 베타다. 글로벌 랭킹까지 무리하게 넣지 않는다.

### 기술 작업

- 첫 플레이에서 백스윙·팔로스루·손 떼기를 알려주는 짧은 안내.
- 새로고침·앱 전환 후 진행 중 라운드 복구.
- 방문 → 첫 샷 → 홀별 완료 → 9홀 완주 → 재도전 측정.
- 오류 수집과 iPhone Safari·Android Chrome 실기기 확인.
- 현재 회귀 테스트를 배포 전 자동 실행.
- 테스트 배포 확인 후 프로덕션 반영하는 절차.
- 오늘 코스와 9홀 총점의 결과 공유.

### 검증 기준

테스터 30~50명을 모집하고 다음을 초기 가설로 삼는다.

| 지표 | 초기 목표 | 분모·정의 |
|---|---|---|
| 첫 샷 성공률 | 80% 이상 | 게임을 시작한 사람 중 유효한 첫 샷을 발사한 사람. 홀인원 성공률이 아님 |
| 첫 라운드 완주율 | 50% 이상 | 첫 라운드를 시작한 사람 중 9홀을 완료한 사람 |
| 다음 날 재방문율 | 20% 이상 | 첫 방문일의 다음 날 다시 방문한 사람의 비율 |

업계 표준이나 성공 보장이 아닌 초기 판단 기준이다. 표본이 작으므로 수치와 함께 중단 이유를 직접 듣는다. 실제 관측 전에는 달성했다고 표현하지 않는다.

### 하지 않을 것

광고·결제·클럽 능력치·장비 상점·새 코스 대량 제작.

## 3. 다음 단계: 공정한 온라인 랭킹

예상 작업량은 추가 2~4주다. 실제 일정은 베타 결과와 서버 검증 범위에 따라 조정한다.

| 영역 | 추천 | 이유 |
|---|---|---|
| 게임 화면 | 기존 HTML + Three.js 유지 | 프레임워크 재작성의 이익이 작음 |
| 사용자 식별 | 게스트로 시작 | 플레이 전 가입 장벽 제거 |
| DB·인증 | Supabase | 1인의 DB 서버 관리 부담 감소 |
| 점수 검증 | 서버리스 API | 실시간 멀티플레이 서버 없이 샷 검증 |
| 초기 플랫폼 | 모바일 웹 | 기존 배포 구조와 공유 URL 활용 |

게스트 계정은 브라우저 데이터를 지우면 접근을 잃을 수 있다. 이후 기록 보존을 원하는 사람에게 계정 연결을 선택적으로 제공한다. 익명 계정 생성에도 남용 방지가 필요하다.

참고: [Supabase 익명 인증 안내](https://supabase.com/docs/guides/auth/auth-anonymous)

### 점수 검증 흐름

1. 서버가 라운드 ID·오늘 코스·물리 버전을 발급한다.
2. 클라이언트가 각 홀의 샷 입력값을 제출한다.
3. 서버가 동일한 물리 계산으로 결과와 점수를 재계산한다.
4. 홀 순서·중복 제출·입력 범위·라운드 유효성을 확인한다.
5. 9홀을 마친 라운드만 공식 랭킹에 반영한다.

프런트엔드와 서버는 동일한 물리 모듈을 공유해야 한다. 계산식을 서로 복사해 유지하지 않는다. 서버리스 API도 백엔드다. 동시 접속자 수가 많아질 때가 아니라 공식 점수를 신뢰해야 할 때 백엔드가 필요하다.

서버 재계산도 자동으로 최적 샷을 찾는 봇까지 막아주지는 않는다. 초기에는 요청 제한·비정상 기록 검토를 적용하고 현금이나 상품이 걸린 경쟁은 하지 않는다.

### 랭킹 규칙 제안 — 구현 전 확정 필요

- 일간: 같은 일일 코스에서 개인 최고 9홀 점수.
- 주간·월간: 기간 내 일간 최고 점수의 합.
- 날짜 기준: 서버의 한국시간 00시로 통일하고 화면에 명시.
- 연습 기록과 공식 기록을 구분.

주·월 합산은 재방문을 유도하지만 자주 참여한 사람이 유리하다. 이 특성을 숨기지 않고 기간 챌린지로 설명한다. 위 규칙은 제안이며, 사용자 확정 없이 구현하지 않는다.

## 4. 재방문이 확인되면 광고 도입

첫 수익화는 9홀 종료 후 광고를 추천한다.

- 샷 중간이나 홀마다 광고를 넣지 않는다.
- 광고 시청으로 공식 랭킹 점수를 올리거나 재샷하게 만들지 않는다.
- 모바일 웹용 AdSense H5 Games Ads 신청 가능 여부를 먼저 확인한다.
- 제품 지원과 개별 게임 승인은 별개이며 승인·노출·수익을 보장하지 않는다.

참고: [AdSense H5 Games Ads 시작 안내](https://support.google.com/adsense/answer/9959170?hl=en)

### 수익 계산

월수익 ≈ 일 이용자 × 1인당 일 실제 광고 노출 × 30 ÷ 1,000 × 실측 eCPM

예시: 일 이용자 1,000명 × 하루 광고 2회 × 30일 ÷ 1,000 × eCPM 2,000원 = 월 12만원.

계산 예시일 뿐 수익 예측이 아니다. 실제 노출률·국가·광고 차단 등에 따라 달라진다. 광고 SDK보다 매일 방문하는 사람을 확보하는 일이 더 어렵다.

## 5. 예산과 출시 준비

기존 GitHub와 연결된 Vercel 프로젝트를 그대로 유지한다. 새 프로젝트를 만들거나 연결을 바꾸지 않는다.

- Vercel Hobby는 비상업용 조건이다. 상업 서비스 운영에는 적합한 요금제를 확인한다.
- 확인 당시 Vercel Pro 기본요금은 월 $20이며 사용량 추가 비용과 세금이 있다.
- Supabase 무료 플랜으로 검증을 시작하고, 필요하면 월 $25부터인 Pro 전환을 검토한다.
- 초기 추천은 Vercel Pro + Supabase 무료다. 실제 전환·결제는 별도 승인 후 진행한다.
- 월 10만원은 초기 인프라 예산으로 계획할 수 있으나 트래픽 초과분·환율·세금·도메인·개발 도구 구독 포함 여부를 별도로 계산한다.
- 가격과 조건은 변경될 수 있으므로 구매·출시 직전에 재확인한다.

출처:

- [Vercel 이용조건](https://vercel.com/legal/terms)
- [Vercel 요금표](https://vercel.com/pricing)
- [Supabase 요금표](https://supabase.com/pricing)

### 공개 출시 전 체크리스트

- 제공 국가에 따른 게임물 등급분류·신고 대상 여부 확인.
- 실제 수집 데이터에 맞는 개인정보 안내와 삭제 절차.
- 광고·분석 도구의 동의 처리 요건 확인.
- 사용 음원·그래픽의 상업 이용 근거 보관.
- 문의 창구, DB 백업·복구, 비용 알림.
- 랭킹 오류·부정 기록 대응 기준.

단순한 웹게임이라는 이유로 법적 요건이 없다고 가정하지 않는다. 이 문서는 개별 서비스의 법적 적합성 판정이 아니다.

## 6. 가장 가능성 높은 실패 이유

1. 몇 번 치고 나면 다시 올 이유가 없다. 랭킹만 추가한다고 해결되지는 않는다.
2. 게임은 만들었지만 사람을 데려올 통로가 없다. 방문자가 없으면 광고 수익도 없다.
3. 스윙 결과나 순위를 신뢰하지 못한다. 이해되지 않는 조작이나 비정상 상위 기록은 경쟁을 무너뜨린다.

## 다음 실행 항목

첫 플레이 안내 + 이용 지표 + 라운드 복구를 먼저 구현한다. 베타로 완주와 재방문을 확인한 뒤 서버 검증이 있는 온라인 랭킹을 만든다.
