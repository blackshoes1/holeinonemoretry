## 1단계 — 첫 2주 베타

```text
공통 지침을 지키면서 소규모 베타에 필요한 첫 플레이 안내·이용 지표·라운드 복구·공유·검증 절차를 구현해줘. 온라인 랭킹·광고·결제는 이번 범위가 아니다.

1. 첫 플레이 안내
- 실제 B 방식과 일치하는 짧은 안내: 조준 → 아래로 백스윙 → 위로 팔로스루 → 손을 떼면 샷.
- 최초 표시, 건너뛰기, 다시 보기만 지원한다.
- 안내 UI가 게임 입력을 오작동시키거나 원치 않는 샷을 발사하지 않게 한다.
- 안내 완료·건너뛰기는 기존 기록과 분리해 저장한다.

2. 진행 중 라운드 복구
- 기존 완료 기록 저장과 별도의 버전 있는 진행 상태를 저장한다.
- 코스 시드, 홀 번호, 완료 홀 점수, 누적 결과를 보존한다.
- 홀 종료·라운드 시작 등 필요한 전환점에서 저장하고 매 프레임 저장하지 않는다.
- 복원 안내와 이어하기/새 라운드를 제공한다. 완료 기록을 삭제하지 않는다.
- 비행 중 중단, 자정 경과, 코드 버전 변경 시 복원 정책을 구현 전에 제안하고 확인받는다.
- 불완전하거나 손상된 데이터로 게임이 멈추지 않게 한다.
- 완료 라운드가 복원·새로고침으로 중복 저장되지 않게 한다.
- 저장 실패를 성공처럼 표시하지 않는다.
- 이 단계의 로컬 기록은 공식 랭킹으로 취급하지 않는다.

3. 이용 지표와 오류
- 이벤트를 정의한다: 방문, 라운드 시작, 첫 유효 샷, 홀 완료, 9홀 완주, 재도전, 공유, 복원, 저장 실패, 실행 오류.
- 이벤트 발생 조건·필드·중복 방지 기준을 문서화한다.
- 샷 성공률은 홀인원율이 아니라 유효한 첫 샷 발사 비율로 정의한다.
- 분석 서비스가 이미 연결돼 있는지 먼저 확인한다.
- 없으면 예산·데이터 수집·동의 요건을 설명하고 도구 한 가지를 추천해 승인받는다.
- 승인 전에는 로컬 검증 가능한 이벤트 기록과 전송 경계까지만 만든다. 실제 집계가 된다고 주장하지 않는다.
- 좌표 전체·이메일·불필요한 식별 정보를 수집하지 않는다. 오류 메시지의 민감정보도 주의한다.
- 분석 전송 실패가 게임을 중단시키지 않게 한다.
- 다음 날 재방문 측정에 필요한 식별·날짜 기준과 데이터 한계를 설명한다.

4. 결과 공유
- 9홀 종료 시 날짜/코스 시드·총점·게임 URL을 공유한다.
- 지원 브라우저에서는 네이티브 공유, 미지원 시 텍스트 복사로 대체한다.
- 공유 취소를 오류로 과장하지 않는다. 복사 실패 시 성공 표시 금지.
- 온라인 검증 전이므로 공유 점수를 공식 인증 기록처럼 표현하지 않는다.

5. 배포 전 검증 절차
- 기존 tests/regression.cjs를 활용하고 이번 변경의 회귀 테스트를 추가한다.
- CI가 이미 있으면 확장하고, 없으면 테스트 실행용 최소 구성을 작성한다.
- CI 구성 작성이 현재 GitHub→Vercel 자동 배포를 차단한다고 가정하지 않는다.
- 프로덕션이 테스트 성공 전 배포될 수 있는 현재 연결이라면 이를 보고하고, 보호 설정 변경은 승인받는다.
- 테스트 브라우저는 400x800처럼 고정된 크기로 실행한다.

필수 검증:
- 안내 완료/건너뛰기/다시 보기와 입력 충돌 없음.
- 정상 새로고침 복구, 손상 상태 처리, 선택한 중단·자정 정책.
- 완주 저장과 이벤트의 중복 방지.
- 분석 전송 실패·저장 실패 시 게임 계속 사용 가능.
- 공유 지원·미지원·취소·실패 처리.
- 조준 → 스윙 → 결과 → 다음 홀 → 9홀 완주 → 새로고침 후 기록 유지.
- 기존 물리·사운드·B 방식 회귀 테스트 유지.

목표 지표는 첫 샷 80%, 첫 라운드 완주 50%, 다음 날 재방문 20%를 초기 가설로 문서화한다. 실제 테스터 데이터를 수집하지 않았다면 달성 여부는 미측정으로 보고한다.

구현과 로컬 검증 후 멈추고, 테스트 모집·배포 등 외부 행동은 별도 승인받는다.
```

## 2단계 — 서버 검증과 온라인 랭킹

```text
공통 지침과 1단계 결과를 확인하고, 서버가 검증하는 9홀 온라인 랭킹을 구현해줘. 이 단계는 별도로 실행 요청을 받은 경우에만 시작한다.

먼저 확정할 규칙:
- 일간 개인 최고, 주·월은 일간 최고 합산을 추천하되 사용자에게 확인받는다.
- 한국시간 날짜 경계, 주 시작 요일, 동점 순위, 자정 걸친 라운드 귀속, 허용 시도 횟수와 만료 정책을 확인한다.
- 순위 계산 방식을 임의로 결정하지 않는다.

아키텍처:
- 기존 화면 유지, Supabase DB·게스트 인증, 서버리스 점수 검증 API를 기본안으로 한다.
- 기존 리소스를 먼저 확인한다. DB 생성·유료 변경은 승인받는다.
- 물리 모듈 공유를 위해 필요한 최소 분리만 한다. 계산식·상수는 변경하지 않는다.
- 클라이언트와 서버의 물리·코스·점수 버전을 명시한다.
- 프레임 수가 아닌 동일한 고정 스텝과 종료 규칙으로 계산한다.

공식 샷 흐름:
- 서버가 소유자에 연결된 라운드 ID·코스 시드·버전을 발급한다.
- 샷 입력값의 유효 범위·홀 순서·라운드 만료를 검사한다.
- 클라이언트가 보낸 최종 점수나 착지 좌표를 신뢰하지 않고 서버에서 재계산한다.
- 네트워크 재시도와 중복 요청이 점수를 중복 반영하지 않게 한다.
- 원자적 처리와 유일성 제약으로 동시에 온 중복 제출을 막는다.
- 9홀을 모두 검증한 라운드만 공식 랭킹에 반영한다.
- 검증 API 장애 시 연습 플레이는 가능하되 공식 등록 성공으로 표시하지 않는다.

보안·계정:
- 공식 결과의 클라이언트 직접 쓰기를 금지한다.
- 사용자 소유권과 공개 랭킹 읽기 범위를 검증한다.
- 공개 스키마의 접근권한·RLS를 명시하고 타인 기록 접근/변조 테스트를 한다.
- 비밀키는 서버에만 둔다.
- 익명 가입·샷 제출의 남용 방지와 요청 제한을 적용한다.
- 게스트 계정 접근 상실과 향후 계정 연결의 한계를 안내한다.
- 서버 재계산을 봇 방지 완성이라고 표현하지 않는다. 현금·상품 보상은 추가하지 않는다.

필수 검증:
- 정상 9홀 제출·랭킹 반영.
- 점수 조작·범위 밖 샷·홀 건너뛰기·다른 사용자 라운드 제출 거부.
- 중복/동시 제출·타임아웃 후 재시도에도 한 번만 반영.
- 클라이언트와 서버의 물리 결과 비교 및 기존 벤치마크 유지.
- 확정한 날짜 경계·동점·주·월 합산 규칙.
- 공개 읽기와 비공개 정보 보호, 직접 쓰기 차단.
- 연습 기록이 공식 랭킹에 섞이지 않음.

비용 예상과 백업·복구 방안을 문서화하고 로컬/승인된 테스트 환경에서 검증한다. 승인 없이 프로덕션 DB 변경·push·배포하지 않는다.
```

## 3단계 — 재방문 검증과 운영 준비

```text
공통 지침을 따르고, 측정된 베타 데이터를 기준으로 재방문과 운영 준비를 점검해줘. 이 단계는 별도 요청 후 진행한다.

- 첫 샷·첫 완주·다음 날 재방문 지표를 정의한 분모와 코호트로 계산한다.
- 표본 수·관측 기간·누락·동의 거부 등 측정 한계를 함께 보고한다.
- 실제 데이터가 없으면 가짜 숫자를 만들지 말고 데이터 확보 계획을 제시한다.
- 이탈이 큰 구간을 근거로 개선 한 가지를 추천한다. 기능을 한꺼번에 추가하지 않는다.
- 개선안 승인 후 해당 범위만 구현하고 전후 비교 방법을 남긴다.
- 오늘 코스·내 순위·이전 기록 비교는 기존 데이터로 구현 가능한 범위만 검토한다.
- 알림·메일·친구 초대 발송은 별도 승인 없이 하지 않는다.

운영 준비:
- 오류 확인, 랭킹 이상 기록 검토, 문의 대응, DB 백업·복구, 비용 알림, 배포 롤백 절차를 문서화한다.
- 복구는 테스트 환경에서 실제로 확인하며 운영 데이터를 덮어쓰지 않는다.
- 제공 국가·수집 데이터·광고 계획을 기준으로 등급분류·신고·개인정보·동의 요건의 확인 목록을 작성한다.
- 미확인 법적 요건을 충족했다고 선언하지 않는다.
- 음원·그래픽 라이선스 근거를 점검하되 출처나 권리를 추측하지 않는다.

광고 도입 여부를 이용 데이터·운영 준비 상태에 근거해 추천한다. 광고 SDK나 결제를 이 단계에서 추가하지 않는다.
```

## 4단계 — 승인 후 광고 도입

```text
공통 지침을 따르고, 재방문 검증 결과와 광고 도입 승인을 확인한 뒤 진행해줘.

- AdSense H5 Games Ads의 최신 지원 조건·정책·신청 상태를 공식 문서로 확인한다.
- Vercel 현재 요금제의 상업 이용 조건, 총비용, 필요한 동의 처리를 확인한다.
- 광고 계정·등록 ID·승인 상태가 없으면 임의 값으로 실제 연동 완료라고 하지 않는다.
```
