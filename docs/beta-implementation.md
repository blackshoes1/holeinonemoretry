# 1단계 베타 구현·검증 안내

## 범위

첫 플레이 안내, 진행 중 라운드 복구, 로컬 이벤트, 결과 공유, 테스트 전용 CI를 구현한다. 온라인 랭킹·계정·광고·결제는 포함하지 않는다. 실제 사용자 지표는 아직 미측정이다.

## 저장과 복구 정책

| 저장 키 | 용도 |
|---|---|
| `hio.tutorial.v1` | 안내 완료/건너뛰기. 도움말 버튼으로 다시 열 수 있음 |
| `hio.active.v1` | 라운드 ID·코스 시드·완료 홀 결과·발사 입력·완료 시각 |
| `hio.events.v1` | 최근 300개의 로컬 진단 이벤트 |
| `hio.rounds.v2` | 기존 완료 기록·역대 최고·통산 횟수. 기존 v1 이전 유지 |

사용자가 승인한 정책:

- 비행 중 종료: 발사 직전의 mph·loft·aim·tilt로 같은 샷을 처음부터 재계산한다. 새 샷 입력을 받지 않는다.
- 완료 홀은 보존하고 다음 미완료 홀부터 이어간다. 9홀이 끝난 체크포인트는 결과 화면으로 복원한다.
- 조준/드래그 중 종료: 해당 홀 조준 단계부터 이어간다. 손가락 이동 중인 상태는 저장하지 않는다.
- 자정 경과: 시작한 날의 코스 시드를 유지한다. 개인 기록의 날짜는 기존처럼 완료일 기준이며, 완료 시각을 고정해 나중에 복원해도 날짜가 바뀌지 않게 한다.
- 저장 형식 또는 `RULES_VERSION` 불일치: 이어하기를 제공하지 않는다. 기존 완료 기록은 삭제하지 않는다.
- 단순 문구 수정과 물리·게임 규칙 변경을 구분한다. 호환되지 않는 규칙 변경 시 `beta.js`의 규칙 버전을 올린다.
- 저장은 새 라운드·발사 직전·홀 완료 전환점에서 수행한다. 프레임마다 저장하지 않는다.
- 완료 기록은 라운드 ID로 중복 저장을 막는다. 저장 실패는 화면에 표시한다.

한계:

- 로컬 기록이지 서버가 인증한 공식 기록이 아니다.
- 브라우저 데이터 삭제·차단, 기기 교체 시 복구를 보장하지 않는다.
- 여러 탭이 동시에 같은 저장소를 수정하는 동시성 보장은 없다. 베타는 한 탭 사용을 기준으로 검증한다.
- 완료 ID 중복 검사는 보존된 최근 300개 기록을 기준으로 한다. 그보다 오래된 별도 탭/백업의 재주입은 공식 중복 방지 대상이 아니다.
- 기존에 이미 삭제된 과거 기록을 복원하지 않는다.

## 이벤트 정의

외부 SDK나 서버 전송은 기본적으로 없다. `window.__golf.telemetry.snapshot()`으로 로컬 기록을 확인한다.

| 이벤트 | 발생 조건 | 중복 기준 |
|---|---|---|
| `visit` | 게임 초기화 완료 | 페이지 초기화 ID |
| `round_start` | 실제 새 라운드 시작 | 라운드 ID |
| `first_shot` | 라운드의 첫 유효 샷 발사 | 라운드 ID. 홀인원 성공률이 아님 |
| `hole_complete` | 물리 결과 확정 | 라운드 ID + 홀 번호 |
| `round_complete` | 9번째 홀 결과 확정 | 라운드 ID |
| `retry` | 진행/완료 라운드에서 새 라운드 시작 | 사용자 실행마다 |
| `restore` | 사용자가 이어하기 선택 | 페이지 초기화 ID |
| `share` | 공유 시도 결과 확정 | 사용자 실행마다. 성공/복사/취소/실패 구분 |
| `save_failed` | 안내·진행·완료 기록 저장 실패 | 페이지 + 저장 종류 |
| `runtime_error` | error/unhandledrejection | 페이지 + 오류 종류 |
| `tutorial` | 안내 완료/건너뛰기 | 사용자 실행마다 |

- 허용 필드: roundId, seed, hole, score, method, outcome, reason.
- 이벤트 시각은 UTC ISO 문자열이다. 코스는 기존 브라우저 현지 날짜 시드를 사용한다.
- 이메일·원시 터치 좌표·URL 쿼리·원본 오류 메시지/스택을 기록하지 않는다.
- 최근 300개 범위에서 이벤트 ID를 중복 검사한다. 삭제된 이벤트를 포함하는 영구 집계가 아니다.
- 저장 실패 시 해당 페이지 메모리에는 남지만 새로고침 후 보존은 보장하지 않는다.
- `setTransport(fn)`은 승인된 분석 연동을 위한 경계다. 현재 연결하지 않았으며 과거 로컬 기록을 소급 전송하지 않는다.
- 전송 함수의 동기/비동기 실패는 게임 흐름과 분리하며 자동 무한 재시도하지 않는다.
- 모듈 로딩/렌더러 초기화 이전의 오류는 현재 이벤트 리스너로 수집하지 못할 수 있다.

## 지표와 외부 분석 승인

초기 가설: 첫 샷 80%, 첫 라운드 완주 50%, 다음 날 재방문 20%. 30~50명 테스트 전까지 달성 여부는 미측정이다.

- 첫 샷: 라운드 시작자 중 첫 유효 샷 발사자.
- 첫 라운드 완주: 첫 라운드 시작자 중 9홀 완료자.
- 다음 날 재방문: 같은 익명 이용자를 식별해 첫 방문일 다음 날의 방문 여부를 계산해야 한다.
- 현재 로컬 로그에는 기기 간/서버 공통 이용자 식별자가 없으므로 전체 사용자 수나 재방문율을 집계했다고 주장하지 않는다.
- 실제 분석 도입 시 코호트 날짜 기준을 한국시간으로 통일하고, 익명 식별자의 동의·보존·삭제 정책을 먼저 확인한다. 쿠키 차단, 저장소 삭제, 여러 기기는 집계 오차를 만들 수 있다.

추천 도구는 PostHog 제품 분석이다. 확인 당시 월 100만 이벤트 무료 범위가 있으나 도입 시점에 재확인한다. 승인·프로젝트 설정·수집 안내·동의 요건 검토 전 SDK 삽입이나 외부 전송은 하지 않는다. 자동 수집·세션 녹화는 이번 범위가 아니다.

출처: [PostHog 가격](https://posthog.com/pricing), [공식 FAQ](https://github.com/PostHog/posthog.com/blob/master/contents/faq.mdx)

## 공유

9홀 결과 화면의 버튼으로 날짜/코스 시드·점수·기존 프로덕션 URL을 공유한다. 기기 내 개인 기록이며 공식 랭킹이 아님을 명시한다.

- 네이티브 공유 지원: 해당 API 사용. 취소는 실패 안내를 띄우지 않는다.
- 미지원: 클립보드 복사. 복사 성공 시에만 성공 안내.
- 공유/복사 실패: 재시도 안내. 점수와 게임 진행은 변경하지 않는다.
- 자동 공유·외부 게시·새 URL 발급은 하지 않는다.

## 테스트 실행

```sh
node --input-type=module --check < game.js
node --input-type=module --check < beta.js
node --test tests/*.cjs
```

회귀 기준 커밋 `aec6684`가 필요하므로 CI는 전체 Git 이력을 체크아웃한다. 물리 스윕 때문에 전체 테스트는 수십 초 걸릴 수 있다.

브라우저 확인은 `python3 -m http.server 8140 --bind 127.0.0.1`로 로컬 서버를 실행하고 400×800 화면에서 수행한다. `tests/browser-flow.js`는 테스트 브라우저에만 주입하는 합성 입력 도우미이며 실기기 터치 테스트의 대체물이 아니다.

확인 목록:

- 최초 안내, 완료·건너뛰기·다시 보기, 안내 중 터치/키보드 차단.
- 조준 → 스윙 → 결과 → 다음 홀 → 9홀 완료.
- 비행 중 새로고침, 샷 입력 재사용, 완료 홀 유지, 완료 결과 재복원 시 중복 저장 없음.
- 손상/호환 불가 저장 상태, 저장 차단 안내.
- 공유 지원/미지원/취소/실패와 입력 충돌 없음.
- 로컬 이벤트 중복 방지, 외부 전송 없음, 전송 실패 격리.
- 기존 물리·사운드·B 방식 보존.

## CI와 배포 경계

`.github/workflows/test.yml`은 테스트만 실행한다. Vercel 토큰을 요구하거나 배포하지 않는다.

**이 파일 추가만으로 기존 GitHub→Vercel 자동 배포가 테스트 성공을 기다리는 것은 아니다.** 현재 프로덕션 연결은 유지하며 보호 설정은 변경하지 않았다.

승인 후 권장 절차:

1. 로컬 문법·회귀 테스트 통과.
2. 승인된 비프로덕션 브랜치/PR과 기존 프로젝트의 Preview에서 확인.
3. 필요하면 main 보호 규칙에 필수 테스트를 등록한다. 외부 설정 변경은 별도 승인.
4. 테스트 및 모바일 검증 결과를 사용자에게 보고한다.
5. 사용자가 승인한 경우에만 push/merge/프로덕션 반영한다. main 직접 push 우회 가능성도 함께 점검한다.

현재 워크플로의 GitHub 실행, Preview 배포, 실제 iPhone Safari·Android Chrome의 청음/성능과 공유 시트는 별도 검증 대상이다.

## 로컬 검증 결과 (2026-09-08)

- Node 회귀 테스트 19개 통과. 문법 검사·diff 공백 검사·CI YAML 파싱 통과.
- 기존 물리 코어 비교와 100/130/180m 스윕 결과 동일. 원본 타격음 바이트 동일.
- 400×800 브라우저: 최초 안내·건너뛰기·다시 보기·안내 중 터치/키보드 차단 확인.
- 비행 중 새로고침: 체크포인트 입력 불변, 실제 재계산 결과 일치(첫 홀 3점).
- 홀 완료 후 재복원: 1홀 결과를 유지하고 2홀부터 이어짐.
- 복구를 거쳐 9홀 완주: 321점, 통산 1회. 첫 샷 1·홀 완료 9·완주 1 이벤트 확인.
- 완료 화면 새로고침 후 이어하기: 통산 1회와 완주 이벤트 1회 유지.
- 호환 불가 규칙 버전: 이어하기 차단, 기존 완료 기록 보존.
- 저장 실패 주입: 명시적 실패 안내와 함께 조준·발사 동작 가능.
- 공유 API를 모의한 브라우저 테스트: 공유 성공·취소·복사·실패 모두 점수와 게임 단계를 보존.
- 320×568 화면에서도 안내와 두 버튼이 화면 안에 표시됨.
- 테스트 중 처리되지 않은 브라우저 오류는 관찰되지 않음.

위 결과는 로컬 자동화·모의 API 검증이다. 실제 휴대폰 조작·청음·60fps, 네이티브 공유 시트, 실제 방문자 지표, GitHub CI 실행, 외부 분석 연동·배포는 검증하지 않았다.
